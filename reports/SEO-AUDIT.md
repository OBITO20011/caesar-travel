# تقرير SEO الإنتاجي — شركة قيصر للسياحة والسفر والحج والعمرة

**التاريخ:** 8 أغسطس 2026

**الموقع:** https://caesar-travel.pages.dev

**الإطار:** React + Vite على Cloudflare Pages

## النتيجة التنفيذية

تم تجهيز الموقع للفهرسة والإعلانات الاجتماعية والبيانات المنظمة دون تغيير الألوان أو التخطيط أو الحركات أو وظائف الحجز والإدارة.

- تدقيق SEO الآلي: **686 فحصًا ناجحًا، 0 أخطاء، تحذيران تقنيان معروفان**.
- خريطة الموقع: **73 رابطًا أساسيًا حاليًا**، تشمل الصفحات الثابتة والرحلات والفنادق والتأشيرات المنشورة من Supabase.
- TypeScript: ناجح دون أخطاء.
- ESLint: ناجح دون أخطاء، مع 6 تحذيرات Fast Refresh قديمة في مكونات UI مشتركة.
- بناء Vite الإنتاجي: ناجح.
- اختبار المتصفح: عنوان ووصف وcanonical وOpen Graph وJSON-LD واحد فقط لكل صفحة، دون تكرار.
- اختبار الهاتف 390×844: لا يوجد تمدد أفقي، والعنوان الرئيسي والتنقل ظاهران.

## تشخيص مشكلة Google Search Console

- لقطة Search Console تعرض آخر محاولة قراءة في **5 أغسطس 2026** بحالة «تعذّر جلب الملف»، لذلك لا تمثل بالضرورة الوضع الحالي.
- الفحص المباشر الحالي لـ `/sitemap.xml` أعاد HTTP 200 و`application/xml; charset=UTF-8`، والملف قابل للتحليل ويحتوي 73 رابطًا فريدًا.
- لم تتضمن الخريطة أي رابط إدارة أو دخول أو معاينة أو اختبار، وجميع الروابط تستخدم نطاق الإنتاج عبر HTTPS.
- كانت هناك مشكلة فعلية منفصلة: عناوين بعض برامج العمرة الجوية والبرية كانت متطابقة لأنها تعتمد اسم الفندق وحده. تم إصلاحها باستخدام اسم البرنامج ونوع النقل ومسار الرحلة، وأصبح تدقيق العناوين الفريدة بلا أخطاء.

## التحسينات المنفذة

### 1. بيانات SEO لكل صفحة

- عنوان `<title>` ووصف `meta description` فريدان لكل مسار ثابت.
- عناوين وأوصاف ديناميكية لصفحات الفنادق والرحلات والتأشيرات.
- تمييز صفحات العمرة المتشابهة بعنوان البرنامج ونوع النقل «جو/بر» والمسار «مكة فقط/مكة والمدينة».
- canonical كامل يبدأ بـ `https://caesar-travel.pages.dev`.
- وسوم robots وGooglebot، مع `noindex` لصفحات الإدارة وصفحات المحتوى غير الموجود.
- `hreflang` للغة العربية الأردنية و`x-default`.
- إزالة التكرار بين وسوم HTML الأولية ووسوم React بعد تحميل التطبيق.

### 2. Open Graph وTwitter

- `og:title`
- `og:description`
- `og:image` و`og:image:alt`
- `og:url`
- `og:type`
- `og:site_name`
- `og:locale`
- Twitter Summary Large Image مع العنوان والوصف والصورة والنص البديل.
- صورة مشاركة اجتماعية مخصصة بحجم 1200×630.

### 3. البيانات المنظمة JSON-LD

- كيان موحّد من نوعي `Organization` و`TravelAgency`.
- الاسم العربي والاسم الإنجليزي والرابط والشعار والصورة والعنوان وأرقام التواصل والبريد.
- روابط Facebook وInstagram.
- توحيد الاسم الرسمي إلى «شركة قيصر للسياحة والسفر والحج والعمرة» في H1 وOpen Graph والـ manifest وJSON-LD.
- تنظيف الروابط الظاهرة و`sameAs` لتستخدم الروابط الرسمية المباشرة بلا معاملات تتبع.
- `WebSite` مرتبط بالناشر.
- `BreadcrumbList` لكل صفحة داخلية مفهرسة.
- منع تكرار نفس البيانات المنظمة بعد تشغيل React.

### 4. robots وsitemap

- `robots.txt` يسمح بالزحف ويربط `sitemap.xml`.
- عدم حجب `/admin` في robots حتى يتمكن محرك البحث من قراءة توجيه `noindex`.
- توليد sitemap تلقائيًا قبل كل build.
- اكتشاف المسارات الثابتة الجديدة من ملفات TanStack Router.
- قراءة الرحلات والتأشيرات العامة المنشورة من Supabase أثناء البناء.
- استبعاد المحتوى المخفي والمنتهي ومسارات الإدارة.
- كتابة `lastmod` بصيغة Google القياسية `YYYY-MM-DD` والتحقق من عدم وجود روابط مكررة أو غير إنتاجية.
- توليد HTML منفصل لكل رابط معروف حتى تصل العناوين والـ canonical لمحرك البحث مباشرة.

### 5. الأيقونات والـ Manifest

- `favicon.ico`
- أيقونات 16×16 و32×32
- Apple Touch Icon
- Android 192×192 و512×512
- أيقونة maskable
- Manifest عربي RTL كامل مع الاختصارات والألوان.

### 6. الصور والأداء

- إضافة `alt` و`title` و`loading` و`width` و`height` إلى جميع عناصر `<img>`.
- استخدام `loading="lazy"` للصور غير الحرجة.
- الإبقاء على صور LCP الرئيسية `eager` مع `fetchPriority="high"` لأنها يجب أن تبدأ مبكرًا.
- إضافة `decoding="async"` للصور.
- ضغط 19 صورة كبيرة من PNG إلى JPEG عالي الجودة:
  - قبل: 42,390,114 بايت.
  - بعد: 5,746,924 بايت.
  - التخفيض: **86.4%**.
- تخفيض شعار الهيدر المستخدم من نحو 322 كيلوبايت إلى 25.45 كيلوبايت.
- فصل مساعد قيصر إلى حزمة lazy مستقلة.
- الحزمة الرئيسية:
  - قبل: 295.80 كيلوبايت، gzip 94.55.
  - بعد: 223.39 كيلوبايت، gzip 69.13.
  - التخفيض التقريبي: **24.5%** للحزمة و**26.9%** بعد gzip.
- إضافة preconnect وdns-prefetch لخطوط Google مع `display=swap`.
- سياسات cache طويلة للأصول ذات البصمة، وسياسات مناسبة للصور وملفات الزحف.

### 7. الوصول والبنية الدلالية

- رابط “تجاوز إلى المحتوى الرئيسي”.
- تنقل رئيسي دلالي مع اسم ARIA.
- تركيز لوحة مفاتيح واضح عبر `:focus-visible`.
- احترام `prefers-reduced-motion`.
- تحسين تسلسل H1/H2/H3 في الصفحات التي كانت تستخدم مستويات غير صحيحة.
- H1 دلالي لصفحة دخول الإدارة مع المحافظة على نفس الحجم المرئي.
- أسماء ARIA وautocomplete لحقول دخول الإدارة.
- روابط خارجية آمنة باستخدام `noopener noreferrer`.

### 8. الحماية على Cloudflare Pages

- Content Security Policy.
- `X-Frame-Options: DENY`.
- `X-Content-Type-Options: nosniff`.
- `Referrer-Policy: strict-origin-when-cross-origin`.
- Permissions Policy للكاميرا والميكروفون والموقع والدفع والحساسات وUSB.
- `X-Robots-Tag: noindex, nofollow, noarchive` لمسارات الإدارة.
- تغطية `/admin` و`/admin/*` صراحة في ترويسات Cloudflare.
- إضافة حماية Git لمنع تتبع جميع ملفات `.env.*` مع السماح بملف مثال آمن فقط.

## التحذيرات المتبقية

1. **SearchAction غير مضاف عمدًا.** Google أوقف ميزة sitelinks search box في 21 نوفمبر 2024، والموقع لا يملك صفحة بحث URL حقيقية. إضافة SearchAction وهمي ستكون بيانات منظمة غير صحيحة. إذا أضيف بحث حقيقي لاحقًا يمكن إضافة الإجراء له.
2. **المسارات العشوائية غير المعروفة قد تستلم HTTP 200 من fallback الخاص بـ SPA.** واجهة الموقع تعرض صفحة 404 صحيحة مع `noindex`، لكن إرجاع HTTP 404 فعلي لكل URL ديناميكي غير معروف يحتاج Cloudflare Pages Function أو SSR.
3. **ستة تحذيرات ESLint قديمة** تخص تصدير helpers بجانب مكونات shadcn UI وتأثير ذلك على Fast Refresh أثناء التطوير فقط؛ لا توجد أخطاء lint أو أخطاء إنتاجية.
4. **Core Web Vitals الحقيقية تحتاج قياسًا بعد النشر.** لا يمكن اعتبار Lighthouse المحلي أو البناء وحده بيانات ميدانية؛ يجب مراجعة PageSpeed Insights وSearch Console بعد وصول النسخة إلى Cloudflare.
5. **المحتوى الديناميكي الجديد يحتاج build جديدًا** ليُضاف إلى sitemap وHTML الخاص بمحركات البحث. العملية آلية في كل build، لكنها ليست تحديثًا لحظيًا لحظة الحفظ في لوحة الإدارة.
6. **HTTP HTML يحتوي بيانات الرأس مسبقًا، بينما محتوى الصفحة يُرسم عبر JavaScript.** Google يدعم معالجة JavaScript، لكن SSR كامل يمكن أن يحسن اكتشاف المحتوى لدى الزواحف الأقل قدرة مستقبلًا.
7. **النطاق الحالي `pages.dev` صالح للفهرسة**، لكن شراء نطاق رسمي باسم الشركة وربطه لاحقًا يدعم العلامة والثقة. عند ذلك يجب تعديل `site.url` وإعادة البناء وإضافة Property الجديدة في Search Console.

## خطوات Google بعد النشر

1. إضافة الموقع إلى Google Search Console والتحقق من الملكية.
2. حذف إدخال الخريطة الفاشل القديم إذا بقي ظاهرًا، ثم إرسال `sitemap.xml` فقط في الحقل الذي يسبقُه النطاق تلقائيًا.
3. استخدام URL Inspection للصفحة الرئيسية وصفحات `/umrah` و`/turkey-trip` و`/egypt` و`/visa`.
4. طلب الفهرسة للصفحات الأساسية بعد نشر هذا commit.
5. متابعة تقرير Page indexing وCore Web Vitals خلال الأيام والأسابيع التالية.
6. مراجعة Rich Results Test للبيانات المنظمة، مع العلم أن `TravelAgency` و`Organization` يفيدان Google في فهم الكيان ولا يضمنان Rich Result مرئيًا.

## ملاحظة واقعية

هذه التحسينات تجعل الموقع قابلاً للاكتشاف والفهرسة بصورة صحيحة، لكنها لا تضمن ترتيبًا أولًا فورًا. الظهور لعبارات مثل “قيصر للسياحة والسفر” و“Caesar Travel Jordan” يعتمد أيضًا على عمر الموقع، الروابط الخارجية، نشاط Google Business Profile، المحتوى المحدث، وثقة النطاق.
